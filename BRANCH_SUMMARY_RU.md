# Эталон: вариант 1

Эта ветка предназначена для проверки сокомандником; слияние в основную ветку не выполнялось. База — существующая `sergej/emotion-inference` (15ef350), сама основанная на master. История команды сохранена.

## Архитектура

YuNet находит bbox и пять точек. Shared preprocessing выравнивает RGB-лицо. EfficientNet-B0/ONNX принимает только изображение [1,3,224,224]. Координаты отдельным входом не передаются. Консервативный профиль reliable сохранён по умолчанию; для одинаковой фоточасти экспериментального сравнения используйте `--model variant1` (image-only expanded, models/emotion_consensus).

## Изменения по файлам

- `libs/common/src/common/messages.py`: передача пяти точек/оценки детектора с обратной совместимостью сообщений.
- `libs/common/src/common/face_preprocessing.py`: единая версия bbox/выравнивания для обучения и сервиса.
- `cv-service/src/cv_service/detector.py`, `service.py`, `model/yunet.py`: выдача точек и защита изменения размера/forward общей блокировкой.
- `ai-service/src/ai_service/local_emotion_model.py`: локальный ONNX, проверка метаданных и входа.
- `ai-service/src/ai_service/reliable_emotion_model.py`: калибровка, проверка отражения, явный uncertain, политики общей/поклассовой надёжности.
- `ai-service/src/ai_service/analyzer.py`, `config.py`: выбор image-only моделей и единая подготовка лица.
- `models/`: комплектные ONNX, policy, model cards, checksums. Runtime не привязан к компьютеру автора.
- `tools/project.py`, `predict_image.py`: запуск сервисов/проверок и локального фото; добавлен ясный alias variant1.
- `tools/consensus_*.py`, `train_reliable_head.py`, notebook: повторяемые исследовательские обучения и оценки, без автоматической замены опубликованных весов.
- `reports/`, `VALIDATION.md`, отчёты: метрики, разбиения, источники и ограничения; raw photos/checkpoints/env в Git отсутствуют.
- `tests/`: проверки реального инференса, переносимости путей, сериализации YuNet, landmarks и политики отказов.

## Результаты и интерпретация

Основные предыдущие протоколы: `RELIABILITY_REPORT_RU.md`, `CONSENSUS_REPORT_RU.md`. На strong-consensus контроле804 изображений expanded давал90.5% среди ответов при86.2% coverage; reliable97.7% при38.1% coverage. Это не точность на всех возможных видео.

В последующем парном сравнении архитектур на750 новых для проектных адаптаций снимках (744 лица, пять распространённых классов) этот image-only эталон получил88.44% без отказов;91.39% среди674 ответов (89.87% всех750). Дополнительная геометрия в соседней экспериментальной ветке убедимого выигрыша не показала. Проверки этой ветки повторены отдельно; см. `BRANCH_VALIDATION.md`.

## Что проверить перед выбором

Установку из uv.lock, checksum/inference check, тесты, собственные короткие видео и достаточность количества uncertain. Полный Docker/HTTP/очереди и Windows/macOS здесь независимо не проверены. Нет достоверной оценки всех редких классов и субъектной независимости. После просмотра test нельзя использовать его для дальнейшей настройки и снова называть независимым.

Изменения публикуются только в эту feature-ветку. Ветки master/main не обновлять автоматически. Решение о слиянии принимает команда.
