# Продолжение: согласованная разметка и новый вариант модели

## Результат и решение по запуску

Добавлен режим expanded с отдельными весами и условиями принятия для каждого класса. По умолчанию остаётся прежний reliable: новый кандидат НЕ прошёл заранее заданный критерий замены — его точность среди выданных ответов ниже. Пороги после контрольной проверки не менялись. Никаких commit/push не выполнялось.

На ОДНОЙ новой контрольной части из 804 изображений:

| Вариант | Ответов | Покрытие всех снимков | Совпадений с метками среди ответов | Ошибок |
|---|---:|---:|---:|---:|
| Прежний reliable | 306 | 38.1% | 299/306 = 97.7% | 7 |
| Новый expanded | 693 | 86.2% | 627/693 = 90.5% | 66 |

95% Wilson CI: reliable 95.35–98.89%; expanded 88.06–92.44%. Это разные выбранные подмножества: нельзя приписывать разницу только качеству классификатора. Более частые ответы означают больше возможностей ошибиться. Отказ не считается правильным ответом.

Сам классификатор без отказов улучшился на одинаковых 796 найденных лицах: 76.76% → 86.68%, +9.92 п.п.; paired image bootstrap CI [+7.04,+12.94] п.п. Доля правильных категорических ответов на всех 804 снимках в expanded — 77.99%, а не 90.5%.

Это НЕ прямое сравнение с прежними 91.2% на FER2013 PrivateTest: здесь другие изображения и более согласованные метки. Старый PrivateTest уже просмотрен и в выборе v2 не использовался. Прежний RELIABILITY_REPORT_RU.md сохранён как история/описание default reliable.

## Что сделано с данными

Использованы новые голоса FER+ из официального репозитория Microsoft, по десять разметчиков на изображение. Исходный CSV FER2013 сверён с зеркалом: совпали ВСЕ 35887 строк, пиксели и исходные метки; соответствие с FER+ по строкам и Usage проверено. Это не догадка о порядке файлов. Хеши источников в reports/consensus/source_hashes.json и sources.json.

Оставлены случаи с суммой голосов 10, не менее 6 голосов за один класс, unknown<=1, not-a-face=0. Получилось 26114 строк до разделения и исключения повторов. Изображения дедуплицированы по пикселям; конфликтующих majority-хешей при этом правиле не обнаружено. Отбор сильного согласия делает задачу более однозначной — не следует переносить результат на неоднозначные выражения.

Выбрано 3324 train-изображения, из них 3280 прошли подготовку лица. В восьми классах 38–600 выбранных изображений: редких классов действительно мало. Selection=1094, calibration=819, policy-fit=827 из PublicTest с уточнёнными голосами. Разделы не пересекаются по хешам.

Новая контрольная часть — 804 сильных-consensus изображения из НЕиспользованной части FER2013 Training. Они исключены из нынешнего train и из всех 4568 выбранных изображений прежнего обучения. Внутри неё: anger150, contempt8, disgust1, fear45, happiness150, neutral150, sadness150, surprise150. Это не новые люди с гарантированной независимостью: идентификаторов людей нет, возможное пересечение с исходным HSEmotion pretraining неизвестно. Данные теперь просмотрены, для следующего подбора их нельзя заново называть независимыми.

## Как обучалась модель

EfficientNet-B0/HSEmotion, оригинальные backbone и BatchNorm заморожены. Пять точек YuNet и общий yunet5_similarity_v1 используются одинаково в обучении и сервисе. В качестве цели взято распределение голосов, а не только один жёсткий класс. При выборе train minibatch применяется inverse-square-root частот класса.

Проверены head-оптимизации с разной силой distillation (0/.25/1/4) и checkpoints 100/200/400 шагов. Выбор только по selection: macro-F1 по пяти классам, где в selection >=20 примеров. Редкие три класса не создают ложного впечатления устойчивой оценки по 3–14 примерам. Выиграл вариант без distillation, шаг 200; важно не приписывать финальному варианту эффект ненулевого KL-штрафа. Selection macro-F1: прежний head 0.7027, новый 0.8619. Это разработка, не контрольный результат.

Один и тот же экстрактор признаков проверен на точных RGB-пикселях; часть признаков переиспользована по хешам. Расхождение ONNX-признаков и прежнего PyTorch-кэша на 20 изображениях <=2.15e-6. Финальный ONNX получен заменой ТОЛЬКО classifier.weight/bias в оригинальном графе; свёрточная основа не меняется. Экспорт проверен на 20 реальных изображениях и 40 представлениях: max abs logits difference 5.16e-6, решения совпали 20/20.

## Условия принятия для каждого класса

Температура подбирается на calibration. На policy-fit для каждого предсказанного класса ищется порог с >=20 ответами, точностью >=90% и нижней Wilson-границей >=75%. Если доказательств недостаточно — класс отключается в этом режиме, без замены другим классом.

Текущие пороги: anger .40, happiness .35, neutral .35, sadness .85, surprise .45. fear/disgust/contempt — отказ. Дополнительно обязательно совпадение top-класса на обычном и зеркальном лице. Это условия по данным разработки, не гарантия точности 90% в каждом классе.

Фактически среди ответов expanded на контроле:

| Выданный класс | Правильно / ответов | Precision |
|---|---:|---:|
| anger | 131/138 | 94.9% |
| happiness | 137/142 | 96.5% |
| neutral | 130/165 | 78.8% |
| sadness | 95/96 | 99.0% |
| surprise | 134/152 | 88.2% |

Отказ от метки fear/disgust/contempt НЕ означает, что реальные выражения этих типов никогда не будут ошибочно названы neutral или другим классом. Осталась существенная проблема neutral. Классовые доли PublicTest и новой контрольной выборки различаются; точность среди ответов зависит и от такого сдвига. После обнаружения проблемы пороги не исправлялись по контролю.

Критерий релиза записан ДО оценки: selective accuracy>=90%, coverage>=20%, точность среди ответов не ниже прежнего reliable, raw accuracy не хуже прежнего более чем на1п.п. Итог release_passed=false. Поэтому expanded доступен только явно, основной режим не подменён.

## Запуск

Обычный, более консервативный:

```bash
uv run --no-sync python tools/project.py start --model reliable
```

Новый режим с более частыми ответами, пятью разрешёнными классами и известными ограничениями:

```bash
uv run --no-sync python tools/project.py start --model expanded
uv run --no-sync python tools/predict_image.py path/to/photo.jpg --mode expanded --output result.png
```

Для обычного запуска ни FER+, ни PyTorch не нужны: ONNX и policy уже включены. Не меняйте crop/политику старых весов, чтобы искусственно включить новый режим. Старые веса/режимы сохранены. Номер лица не является идентификатором человека, а класс выражения не определяет внутреннее настроение или психическое состояние.

Реальный кадр прошёл обработчики с пятью точками и новым классификатором. Транспорт/хранилище в памяти; Docker/HTTP/очереди не проверены. На известном снимке с улыбкой expanded выдал happiness. Это регрессионный пример, не самостоятельная оценка accuracy.

Большой кэш признаков не включён, его пересчёт занимает несколько минут. Источники проверяются по SHA-256, веса/политика автоматически не продвигаются в default. Ошибка чрезмерного чтения сжатого кэша в первом проверочном скрипте исправлена; первоначальный процесс остановился по памяти до результатов.

Файлы: reports/consensus/*, models/emotion_consensus/*, tools/consensus_*.py. Повторяемость разработки не делает уже просмотренный контроль заново независимым. После данного эксперимента дальнейшие решения требуют новых отложенных примеров. Windows/macOS/MPS и полный Docker-конвейер в этой среде не проверены. Телеметрия ONNX Runtime остаётся отключённой.
