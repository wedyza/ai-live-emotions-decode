# AI Live Emotions Decode

Учебный конвейер: загрузка видео → кадры в MinIO → очередь RabbitMQ → YuNet находит лица → ONNX-классификатор выражений → результаты в терминале.

## Что нужно для запуска

Python 3.12, uv, Docker Desktop (либо Docker Engine с Compose на Linux), доступные порты 8000/9000/9001/5432/5672/15672. MPS/CUDA для запуска приложения не нужны: модели работают на CPU. Установка зависимостей и Docker-образов требует сети. Датасет и PyTorch для обычного запуска не нужны.

Клонируйте ветку с этими изменениями. Выполняйте команды из корня репозитория:

```bash
uv sync --all-packages --no-dev --python 3.12 --locked
uv run --no-sync python tools/project.py check
uv run --no-sync python tools/project.py infra
uv run --no-sync python tools/project.py start
```

Первая команда создаёт собственную .venv: не копируйте чужое виртуальное окружение. `check` проверяет контрольные суммы комплектных весов и выполняет реальный инференс на синтетическом изображении (это не проверка точности). `infra` запускает docker compose up -d --wait. `start` запускает четыре Python-сервиса и выводит их журналы в один терминал; при завершении одного останавливает остальные. Ctrl+C останавливает только запущенные этим процессом Python-сервисы. Docker остаётся работать. Перед использованием launcher остановите ранее вручную запущенные копии сервисов через Ctrl+C.

Откройте http://localhost:8000/docs → POST /videos → Try it out → выберите короткое MP4 с лицом → Execute. Ответ 201 и frames_count подтверждают подготовку кадров, а не завершение асинхронного анализа. Ищите ALERT с тем же video_id в терминале. Если лица нет, уведомления для кадра нет. Номера лиц не являются постоянными ID людей. Наложения рамок на видео и Telegram пока нет.

Все команды запуска выше одинаковы в PowerShell, macOS и Linux: не требуется синтаксис `VAR=value command`. Windows/macOS должны быть проверены владельцами этих платформ; в данном пакете независимо проверен Linux.

## Выбор модели и настройки

По умолчанию используется комплектная экспериментальная модель `models/emotion_experiment/model.onnx` с соседним `model.onnx.json`. При клонировании оба файла и models/checksums.json должны присутствовать. Не исключайте models/ из коммита; не используйте ссылку на локальный reports/ вместо комплектных весов.

Для исходной модели:

```bash
uv run --no-sync python tools/project.py start --model pretrained
```

Она скачивает исходные веса при первом использовании. `--model experimental` возвращает комплектный вариант. Порядок классов и подготовка новой модели проверяются по метаданным; ошибки загрузки не скрываются подменой модели.

При необходимости скопируйте `config.example.env` в `.env`. Settings читают .env из корня checkout. AI_EMOTION_MODEL выбирает experimental/pretrained. AI_EMOTION_MODEL_PATH и CV_MODEL_PATH могут быть абсолютными, но относительные разрешаются от корня проекта, а не текущей папки терминала. Не публикуйте .env и секреты. Порты/доступы Compose и адреса Python-сервисов необходимо менять согласованно, если defaults заняты.

YuNet защищён общей блокировкой, охватывающей изменение входного размера и forward. Prefetch=1 оставлен консервативным default; повышение не отменяет блокировку. Ошибки обработки уходят в очередь `<queue>.dlq`, автоматически не повторяются. После устранения проблемы можно загрузить короткое видео заново.

Данные инфраструктуры исходного Compose хранятся в tmpfs: они не постоянны. Эти настройки рассчитаны на локальный учебный запуск. Не используйте `docker compose down`, пока нужны временные кадры/очереди.

## Проверки

```bash
uv run --no-sync python -m unittest discover -s tests -v
```

Включены реальный инференс, проверка путей вне cwd, ошибка отсутствующих весов, конкурентный доступ к детектору и регрессия конфликта координаты y с целевой меткой. Подробности выполненных проверок: VALIDATION.md. Полный Docker-запуск из этого пакета в проверочном окружении не выполнен: Docker там отсутствует.

## Повторное обучение — отдельно от запуска приложения

Датасет не хранится в Git. Получите его отдельно и распакуйте в datasets/faces: labels.csv, classes.json, images/. Можно указать другую папку через EMO_DATA_DIR внутри ядра ноутбука. Нужны полные кадры и поля file,x,y,width,height,label,is_dup,split,clip_id,subject_id. Исходную координату y не заменяем: номер класса хранится в target.

```bash
uv sync --all-packages --group training --no-dev --python 3.12 --locked
uv run --no-sync python -m ipykernel install --user --name emotions-project --display-name "Emotions Project"
```

В VS Code выберите это ядро (или Python .venv/bin/python), откройте notebooks/02_train_eval.ipynb. Ноутбук очищен от выводов и диагностических ячеек старого сеанса; его можно выполнять последовательно. Пути по умолчанию относительны проекту. При нестандартном датасете добавьте в первую ячейку до конфигурации:

```python
import os
os.environ["EMO_DATA_DIR"] = "/your/dataset/faces"
```

Это индивидуальная настройка, не публикуйте собственный абсолютный путь в общей версии ноутбука. CPU/CUDA/MPS выбираются автоматически; доступность устройства не гарантирует поддержку всех операций. Веса PyTorch первоначально загружаются из репозитория автора: legacy pickle открывается с weights_only=False, не подставляйте сторонние файлы.

Обучение 2 head + 3 full эпохи — лишь стартовый эксперимент. Исходная модель остаётся кандидатом эпохи 0. Эпоха выбирается по val; test не используется для настройки. Разметку кадров нужно проверить вручную. Нет ground-truth для трёх классов; их качество не оценено. Интервалы ноутбука считаются по роликам, а не участникам. Не объявляйте общий выигрыш только по accuracy.

Результаты записываются в reports/<run_id>, экспорт и сравнение ONNX выполняются на CPU. Экспорт не заменяет комплектную модель автоматически. Для обновления потребуются проверенные веса, metadata, отчёт и новые SHA-256 в models/checksums.json. Большие training-checkpoint .pth и датасет не добавлять в Git. Сводка текущего эксперимента: reports/experiment_summary.json и MODEL_CARD.md.

## Git

Работайте в собственной ветке. Перед коммитом выполните `git status --short`, посмотрите diff. Не используйте бездумно `git add .`: окружения/данные/секреты не должны попадать в репозиторий. Изменения исходников, очищенных ноутбуков, зависимостей, документации, tests/, комплектной модели с metadata/checksums и краткого отчёта публикуются вместе. Коммит и push пользователь выполняет отдельно; основной branch не обновляется автоматически.
