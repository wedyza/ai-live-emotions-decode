# Проверки полной сборки с точками

Сборка из последней доступной копии проекта; прямого доступа к Mac нет. Проверено в Linux/Python 3.12. Изменения на GitHub не отправлялись. Git-история, секреты и виртуальные окружения в архив не входят.

## Что реализовано

YuNet отдаёт bbox, score и пять точек в координатах полного кадра. Сообщения сохраняют точки. Общий обработчик common/face_preprocessing.py выравнивает лицо по глазам, носу и уголкам рта и используется как обучением, так и сервисом. EfficientNet получает выровненное RGB-изображение; отдельного числового входа с точками нет. При отсутствии корректных точек aligned-модель не подменяет выравнивание bbox-кропом. Исходная bbox-модель остаётся режимом по умолчанию.

Датасет: datasets/faces_landmarks. Повторная детекция на всех 3613 сохранённых кадрах, 3613 принято, 0 отклонено. Для каждой строки проверены пять конечных точек, сохранение исходных ID, меток, участников, клипов и split. Все 3613 PNG-превью побитово совпадают с общей функцией подготовки. 54 группы участников, пересечений между split нет. Детальный протокол: datasets/faces_landmarks/data_validation.json. Проверка структуры не удостоверяет правильность выражения лица в унаследованной метке видео.

## Реальные обучения

Запущены два полных эксперимента CLI из одних pretrained-весов enet_b0_8_best_afew: seed 42, batch 16, 2 эпохи головы + 3 всей сети, train 794, validation 183, одинаковые ID и split. Среда обучения: CPU PyTorch 2.15.0+cpu. Test-изображения не оценивались и не использовались для выбора эпохи.

| Вариант | Начальный val macro-F1 | Лучший val macro-F1 | Эпоха |
|---|---:|---:|---:|
| bbox без выравнивания | 0.486668 | 0.486668 | 0 (исходные веса) |
| пять точек + выравнивание | 0.536742 | 0.544039 | 4 |

Разница между выбранными вариантами на validation: +0.057372 macro-F1. Это не оценка независимого обобщения. Вклад самого дообучения aligned-варианта меньше: +0.007297 относительно исходной aligned-модели. Сохранены полные history и настройки/ID: reports/landmark_validation, а также checkpoint и экспорт каждого запуска. Шаблон выравнивания не оптимизировался по test.

## Проверки выполнения

- Свежая установка runtime из uv.lock; 14 unittest прошли, включая одновременные вызовы YuNet, порядок точек, одинаковую подготовку в обучении/сервисе и сохранение разбиения.
- Контрольные суммы моделей и настоящий синтетический инференс tools/project.py check проходят в bbox и aligned режимах. Синтетический ввод не оценивает качество.
- Экспорт каждого нового кандидата сопоставлен с его PyTorch-checkpoint на ВСЕХ 183 validation-изображениях через LocalEmotionModel: 183/183 совпадений класса в каждом режиме. Максимальное абсолютное расхождение logits: bbox 2.00272e-5, aligned 5.72205e-5; допуски rtol=1e-3, atol=1e-4. Файлы export_validation.json лежат рядом с каждым запуском.
- Реальный полный кадр прошёл реальные обработчики: YuNet → Face с пятью точками → анализ ONNX → уведомление, в обоих режимах. Хранилище и брокер заменены транспортом в памяти: это НЕ Docker/RabbitMQ/MinIO интеграционный тест. Повторение: tools/verify_pipeline.py --model aligned.
- Код скриптов и ячеек notebook компилируется. Notebook целиком заново не исполнялся; обучение проверено воспроизводимыми CLI-запусками.

## Что остаётся непроверенным

В этой среде нет Docker: полный запуск инфраструктуры, загрузка через HTTP и очереди не проверены. Не проверены Windows/macOS/MPS/CUDA. Нет независимого нового test на новых людях; старый test раньше просматривался. Ground-truth для contempt/fear/sadness отсутствует. Низкие softmax-оценки нельзя трактовать как достоверное внутреннее состояние человека. Это учебная экспериментальная система.
